## 3) 四类身份架构 12 维矩阵
- 维度1用户规模：External ID 更适配千万级消费者。 [ZH013]
- 维度2目录隔离：CIAM 与员工目录物理隔离更安全。 [ZH014]
- 维度3伙伴互信：B2B 适合大型企业跨租户协作。 [ZH015]
- 维度4存量复用：OIDC换票可快速复用会员中心登录态。 [ZH016]
- 维度5防刷能力：匿名体验需配合WAF、设备指纹和Token封顶。 [ZH017]
- 维度6会话升维：涉及退改/账户操作时必须 Step-Up MFA。 [ZH018]
- 维度7声明驱动授权：`dealer_tier`/`store_id` 可在网关侧即决策。 [ZH019]
- 维度8零数据库回查：APIM按声明执行配额与价格隔离。 [ZH020]
- 维度9风控成本：两段式鉴权兼顾获客转化与防薅羊毛。 [ZH021]
- 维度10运维复杂度：双轨匿名+实名治理复杂但收益高。 [ZH022]
- 维度11最佳场景：External ID 对客，B2B 对伙伴，OIDC换票对存量生态。 [ZH023]
- 维度12反模式：严禁把百万外部会员塞进员工主租户Guest目录。 [ZH024]

## 5) 五组可复算 Q&A
### Q1 Denial-of-Wallet 四层防线测算
- Front Door Bot 防护 + 设备指纹 + 匿名Token封顶 + 登录触发。 [ZH032]
- synthetic示例：高峰恶意请求可拦截 90%+ 预算外消耗。 [ZH033]
### Q2 为什么不能把百万会员塞进员工租户Guest
- 容量、治理、生命周期与审计边界都会被外部账号污染。 [ZH034]
- 独立CIAM租户可清晰隔离凭据、策略与运营流程。 [ZH035]
### Q3 会话中途升维如何不断流
- 公共问答阶段使用匿名/低权限token。 [ZH036]
- 进入敏感操作时触发Step-Up并换发高保证会话声明。 [ZH037]
### Q4 声明驱动配额与价格隔离
- APIM读取`dealer_tier`与`store_id`执行限流与政策隔离。 [ZH038]
- 无需回库即可实现多层伙伴差异化策略。 [ZH039]
### Q5 200万月活身份+网关TCO
- 关键成本来自鉴权调用、网关策略执行与反刷缓存。 [ZH040]
- 通过声明化策略与Redis额度桶可显著降低后端回查成本。 [ZH041]
