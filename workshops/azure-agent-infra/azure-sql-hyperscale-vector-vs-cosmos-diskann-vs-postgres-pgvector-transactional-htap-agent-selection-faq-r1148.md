## 3) 四类事务与向量融合架构 12 维矩阵
- 维度1一致性：SQL/PG/Cosmos 同库写后即读优于 CDC 异步链。 [ZH013]
- 维度2恢复边界：库内向量与业务数据共享 PITR 边界。 [ZH014]
- 维度3扩展性：Cosmos 分区水平扩展更直接。 [ZH015]
- 维度4复杂过滤：SQL/PG 对结构化条件过滤表达更强。 [ZH016]
- 维度5长文语义：AI Search 在分块与语义重排更强。 [ZH017]
- 维度6同步风险：拆库必然引入漏同步与最终一致窗口。 [ZH018]
- 维度7成本模型：库内向量减少双份存储；拆库换来更强检索能力。 [ZH019]
- 维度8权限治理：SQL RLS 与 PG 策略可原生复用。 [ZH020]
- 维度9全球多写：Cosmos 在跨区域多写场景更优。 [ZH021]
- 维度10运维复杂度：拆库链路组件更多，故障面更大。 [ZH022]
- 维度11最佳场景：临床/ERP/库存强一致优先库内；文档密集场景优先拆库。 [ZH023]
- 维度12反模式：不要在高一致业务上忽略 CDC 同步丢失风险。 [ZH024]
## 4) 评分与决策阈值
- Azure SQL Hyperscale：一致性5、过滤5、长文3、复杂度4。 [ZH025]
- PostgreSQL pgvector/pg_diskann：一致性5、过滤5、长文3、复杂度4。 [ZH026]
- Cosmos DiskANN：一致性4、扩展5、过滤3、复杂度4。 [ZH027]
- 业务库+AI Search 拆库：一致性3、长文5、复杂度3。 [ZH028]
- 阈值A：若“错价/无货推荐”不可接受，优先库内融合查询。 [ZH029]
- 阈值B：若非结构化文档占比>70%，拆库检索价值显著。 [ZH030]
- 阈值C：若CDC漏同步风险不能容忍，先做库内向量。 [ZH031]
## 5) 五组可复算 Q&A
### Q1 500万行结构化记录月度TCO
- 库内向量方案省去独立索引存储与CDC链路，synthetic月成本可低 18%~27%。 [ZH032]
- 拆库方案在长文检索质量上更好，但需承担双份存储和同步运维。 [ZH033]
### Q2 高选择率过滤差异
- HNSW后过滤在高选择率下可能召回缩水。 [ZH034]
- DiskANN 迭代过滤更稳，但需更多调优与容量预算。 [ZH035]
### Q3 同步Embedding阻塞 vs Outbox异步补齐
- 同步生成Embedding会放大事务尾延迟。 [ZH036]
- Outbox异步补齐可削峰，但引入秒级一致性窗口。 [ZH037]
### Q4 5000万条1536维向量成本
- 纯内存HNSW规格昂贵；SSD辅助DiskANN常更经济。 [ZH038]
- 需结合P95召回目标和写入速率做容量曲线。 [ZH039]
### Q5 何时从库内向量升级到拆库
- 当长文检索和语义重排成为主瓶颈且可接受最终一致时再升级。 [ZH040]

## 7) 场景A：连锁医疗集团病历写后即读临床辅助
- 基于 Azure SQL Hyperscale 向量与院区/科室级 RLS。 [ZH048]
- 门诊病历与检验指标落库即做相似病例匹配。 [ZH049]
- 医嘱集推荐必须命中租户与科室权限边界。 [ZH050]
- 不搬运敏感病历到多套外部系统，降低合规风险。 [ZH051]
- synthetic收益：诊疗辅助响应时延下降 39%。 [ZH052]
## 8) 场景B：B2B工业品MRO平台 1500万SKU替代件推荐
- SKU属性、协议价、实时库存在 PG/Cosmos 同库同查。 [ZH053]
- 防止推荐无货或错价商品，强一致优先。 [ZH054]
- PDF规格书与安装手册交给 AI Search 长文检索。 [ZH055]
- 混合查询先过客户目录和库存过滤再做向量相似。 [ZH056]
- synthetic收益：无效推荐率下降 44%。 [ZH057]
