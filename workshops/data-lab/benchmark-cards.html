以 OneLake 零拷贝与 Fabric IQ 本体收拢业务语义入口，与 Databricks/Snowflake/GCP/AWS 建立高胜率互补共存

AI Solution Architect 实战选型结论：在实际企业落地中，“单一选型推翻重来”阻力巨大；通过 OneLake Mirroring / Shortcuts 将异构云数仓无缝转化为 AI Ready 本体底座是最高胜率打法。

✅ Good fit（必赢与高优共存场景）

  • M365 Copilot & Power BI 重度企业：直接复用存量语义模型与 Purview/Entra 权限，在 Copilot Chat/Cowork 中享零额外 AI Token 成本（GA）。
  • 实时运营数字孪生 (RTI + Ontology)：智算中心能源调度、机场跑道/物流监控等需 Eventstream → Eventhouse KQL → Operations Agent 亚秒级闭环的场景。
  • 跨云零 ETL 共存 (Better Together)：源端保留 Snowflake / Databricks / BigQuery / AWS S3 Tables / Salesforce Data 360，通过 OneLake Mirroring & Shortcuts 零搬迁构建全域 AI 问数。
  • 分析即行动 (Agentic BI Apps)：利用 Power BI Agentic App Creation + 1GB 免费 Fabric SQL 快速交付带数据回写（Write-back）的业务微应用。

⛔ Not for（避坑边界与反模式）

  • 超大规模基础模型预训练 / 深度算子定制：百亿参数分布式预训练与底层 CUDA/DeepSpeed 调优应路由至 Databricks Mosaic AI 或 Azure ML / Foundry GPU 集群，而非放入 Fabric Spark。
  • 无语义模型的裸表直接挂接 Agent：跳过语义层与 Ontology 直接对原始湖仓表开放 NL2SQL（如 DL-23），极易引发口径漂移与合规越权。
  • 强行推翻客户已稳定运行的异构核心数仓：当客户在 Snowflake/BigQuery 已有重资产 ETL 时，应主打 Mirroring + Apache Ossie 语义互通，切忌首期强推全量重写。
  • 完全物理断网的纯边缘单机推理：Fabric 为云端 SaaS，断网环境应采用 SQL Server on Azure Local + ALDO (GA)。
