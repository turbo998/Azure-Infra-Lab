Azure Databricks vs. Microsoft Fabric — 10-Dimension SA Selection & Coexistence Battlecard

Core Principle: Both are first-party Azure services (both count toward Microsoft MACC) sharing ADLS Gen2 + Delta Parquet. Over 70% of mature enterprise accounts run a Zero-Copy Better-Together architecture.

2. Four Customer Archetypes & Recommended Reference Patterns

🏢 Archetype 1: M365-Centric Global Operations (e.g., TCL Channel IQ)

  • High Power BI adoption; needs unified SAP/EDI/POS visibility + real-time operational guardrails.
  • Lead with Microsoft Fabric (OneLake Shortcuts + Eventhouse KQL + Fabric IQ Ontology + Direct Lake).

🧪 Archetype 2: Code-First Data Engineering & Multi-Cloud AI Teams

  • Large PySpark/ML teams standardized on Git/DABs, MLflow 3.0, and custom Spark/Ray pipelines.
  • Lead with Azure Databricks (Unity Catalog + Lakeflow + Mosaic AI + AI/BI Genie).

🤝 Archetype 3: Hybrid Enterprise "Better-Together" (e.g., Zava Retail)

  • Existing Azure Databricks medallion & ML backbone + enterprise-wide Power BI & Teams consumption.
  • Mirrored Unity Catalog in OneLake + Power BI Direct Lake (zero ETL copy, single storage footprint).

⛔ Anti-Patterns to Avoid in Customer Designs

  • Never copy Databricks Delta tables via scheduled ETL into Fabric Warehouse — use Zero-Copy Mirrored UC instead.
  • Avoid legacy JDBC scheduled Power BI Imports on large Gold tables — switch to Direct Lake.
  • Never expose raw tables to LLM agents without UC Metric Views or Fabric IQ Ontology rules.
