## 3) 12-dimension matrix for transactional-vector architectures
- D1 consistency: SQL/PG/Cosmos in-database write-after-read beats async CDC paths. [EN013]
- D2 recovery boundary: in-db vectors share PITR boundary with business tables. [EN014]
- D3 scale: Cosmos partition-based horizontal scale is straightforward. [EN015]
- D4 filtering: SQL and PG offer stronger complex business predicates. [EN016]
- D5 long-form semantics: AI Search leads in chunking and reranking. [EN017]
- D6 sync risk: split-store introduces eventual-consistency windows and missed-sync risk. [EN018]
- D7 cost shape: in-db vectors avoid duplicate storage while split-store boosts retrieval quality. [EN019]
- D8 governance: SQL RLS and PG policy controls are reusable. [EN020]
- D9 global writes: Cosmos excels in multi-region write scenarios. [EN021]
- D10 ops complexity: split-store has more moving components and failure surfaces. [EN022]
- D11 best-fit: strong-consistency ERP/HIS/inventory prefers in-db, document-heavy semantics prefers split-store. [EN023]
- D12 anti-pattern: never ignore CDC loss risk on high-consistency business flows. [EN024]

## 5) Five calculable Q&As
### Q1 Monthly TCO for 5 million structured records
- In-database vectors remove duplicate index storage and CDC chains, often saving 18% to 27% monthly in synthetic estimates. [EN032]
- Split-store yields stronger long-form retrieval but carries duplicate storage and sync operations cost. [EN033]
### Q2 High-selectivity filter behavior
- Post-filter HNSW can lose effective recall under high-selectivity predicates. [EN034]
- DiskANN iterative filtering is steadier but requires capacity and tuning budget. [EN035]
### Q3 Synchronous embeddings vs outbox async backfill
- Synchronous embedding generation inflates transaction tail latency. [EN036]
- Outbox async backfill smooths writes but introduces second-level consistency windows. [EN037]
### Q4 Cost shape for 50 million vectors at 1536 dims
- Pure memory HNSW is expensive, while SSD-assisted DiskANN is often more economical. [EN038]
- Capacity sizing must align with p95 recall latency and write throughput goals. [EN039]
### Q5 Upgrade boundary from in-db vectors to split-store
- Upgrade when long-form semantic ranking dominates value and eventual consistency is acceptable. [EN040]
